# Лапки — Android

Нативное приложение на React Native, TypeScript и Expo SDK 57, подключённое к существующему FastAPI `/api/v3`.

Покупательские экраны: каталог товаров и питомцев, поиск и фильтры, карточки и галерея, вход, гостевая/серверная корзина, объединение при входе, контакты и адрес, оформление, тестовая оплата, история и отмена заказов. Используются готовые подтверждённые аккаунты; административных экранов, регистрации и восстановления пароля нет.

## Репозиторий и ветки

`master` — стабильная версия приложения; `dev` — ветка дальнейшей разработки. На момент первой публикации обе ветки содержат версию 0.1.3.

```powershell
git clone https://github.com/AndreyMetelkin85/lapki-mobile.git
cd lapki-mobile
git switch dev
npm ci
```

Backend запускается отдельно из [swagger-petstore](https://github.com/AndreyMetelkin85/swagger-petstore); web-клиент находится в [lapki-frontend](https://github.com/AndreyMetelkin85/lapki-frontend). Мобильный репозиторий содержит Android-клиент, ресурсы, тесты и скрипты сборки.

## Оформление «Лапки»

Утверждённый знак — кремовая лапа с подушечкой в форме сердца на тёмно-зелёном фоне. По уточнённому выбору пользователя значок телефона тоже содержит надпись «Лапки»: используется именно утверждённый PNG `lapki-logo.png`. Адаптивный слой содержит это изображение целиком с техническими полями; фигуры и шрифт не перерисовываются. Отдельной версии для тематических иконок нет. Этот же логотип показывается на нативной заставке, во время чтения локальных настроек, в каталоге, аккаунте и на экране входа. Заставка скрывается после подготовки сессии и настроек; ответа API для этого ждать не нужно.

Файлы находятся в `assets/branding`: `lapki-icon.png` и `lapki-logo.png` — утверждённые изображения, созданные встроенным `image_gen`; `lapki-foreground.png` — экспорт исходного значка для Android. Повторный экспорт: `npm run branding:export`. Перед экспортом проверяется SHA-256 утверждённого исходника. Промпты и происхождение ресурсов записаны в `assets/branding/generation.json`.

Изменение значка и нативной заставки требует новой сборки APK. [Настройка Expo](https://docs.expo.dev/versions/v57.0.0/sdk/splash-screen/) · [Адаптивные значки Android](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive).

## Разработка на Windows

1. Запустите существующий Docker Compose магазина. Проверьте `http://localhost:8080/api/v3/health`.
2. Установите Node.js 22.13+ или Node 24 LTS, JDK 17, Android Studio с Android SDK Platform 36, Platform Tools и Android Emulator. Настройте `JAVA_HOME`, `ANDROID_HOME` и PATH для `platform-tools`.
3. Создайте и запустите эмулятор Android 16 / API 36. Для ускорения нужны виртуализация и Windows Hypervisor Platform.
4. В папке приложения выполните:

```powershell
npm ci
npm run android
```

Команда создаёт Android-проект из `app.json`, собирает и устанавливает собственное приложение `com.lapki.training`, затем запускает Metro. В дальнейшем для изменений TypeScript достаточно `npm start`, если debug-приложение уже установлено.

[Android-среда Expo](https://docs.expo.dev/get-started/set-up-your-environment/?buildEnv=local&device=simulated&mode=development-build&platform=android) · [Локальная сборка](https://docs.expo.dev/guides/local-app-development/)

## Подключение к API

По умолчанию используется `http://10.0.2.2:8080/api/v3`: в стандартном Android Emulator `10.0.2.2` ведёт на Windows-компьютер. Подходит текущему Compose с API на `127.0.0.1:8080`.

Другой адрес можно задать в приложении: **Аккаунт → Подключение**. Смена сервера завершает сессию; гостевая корзина хранится отдельно для каждого адреса. Также можно использовать `.env.example` перед сборкой. Сохранённая настройка приложения имеет приоритет.

Для телефона по USB:

```powershell
adb reverse tcp:8080 tcp:8080
```

Тогда адрес в приложении — `http://127.0.0.1:8080/api/v3`. Для Wi-Fi нужны LAN-адрес Windows, доступная публикация API-порта и настройка firewall. Docker-имя `backend` и эмуляторный `10.0.2.2` обычному телефону не подходят.

В этом учебном приложении разрешён HTTP. Секрет JWT и пароль базы данных не передаются в Android-клиент.

## Автономный APK

С установленным на Windows Android SDK:

```powershell
npm run android:release
```

Либо через Docker Desktop с Linux-контейнерами, без Android SDK на Windows:

```powershell
npm run build:apk:docker
```

Результат: `artifacts/lapki-android.apk`. Сборка по умолчанию для эмулятора x86_64. Для большинства физических телефонов:

```powershell
powershell -NoProfile -File scripts/build-apk.ps1 -Architecture arm64-v8a
```

Установка:

```powershell
adb install -r artifacts/lapki-android.apk
```

APK содержит JavaScript внутри и работает без Metro. Для локального запуска используется учебная подпись сгенерированного Android-проекта; публикация требует собственного release-ключа. Первая Docker-сборка скачивает JDK, SDK, NDK и Gradle.

## Данные и оплата

- В каталоге показываются только опубликованные, заполненные карточки: название, описание, категория, положительная цена, фотография из медиахранилища и обязательные характеристики. Для корма нужны бренд, форма, возраст и вес. Старые записи с пустыми полями или фиктивными `photoUrls` остаются в API, но не попадают в мобильную витрину. Отсутствие остатка или резерв питомца не скрывают заполненную карточку.
- JWT хранится в SecureStore. Пароль не сохраняется. При истечении сессии нужно войти снова: refresh-токена в backend нет.
- Гостевая корзина и безопасные метаданные незавершённых операций — в AsyncStorage, отдельно для серверов и пользователей.
- Цены, остатки и статусы подтверждает backend. Изменившиеся цены требуют повторной проверки корзины.
- Повтор оформления использует прежние ключи. После неопределённого ответа оплаты сначала проверяется сервер; повтор той же попытки не получает новый ключ.
- Номер карты, CVV и имя владельца не сохраняются и не выводятся в логи.

Симулятор: `4242424242424242` — успех; `4000000000000002` — отказ; `4000000000009995` — недостаточно средств. Учебный срок: 12/2099, CVV: 123.

Начальный аккаунт новой БД: `test@example.com / password123`. В существующей базе пароль или состояние аккаунта могли измениться.

## Проверки разработчика

```powershell
npm run typecheck
npm run lint
npm test
npm run bundle:android
```

Unit-тесты проверяют заполненность карточек каталога, деньги, валидацию, объединение корзин и восстановление оформления/оплаты после потерянных ответов. К рабочей БД они не обращаются. У элементов есть семантические `testID`; повторяющиеся карточки выбираются по содержимому строки.

Проверено 13 октября 2026: TypeScript и ESLint проходят. Экспорт слоя значка проверен против прямого размещения утверждённого `lapki-logo.png` в полях Android; совпадение PNG подтверждено, исходник сохраняет SHA-256 `39d110962f2f9cabf0ae8e511299968ca329f61e0cbbfa0be495b9cb50cd12b8`. Ранее пройдены 17 unit-тестов и Expo Doctor — 21/21; бизнес-логика и зависимости после этих проверок не изменялись. Новую версию 0.1.3 нужно установить и проверить вручную на эмуляторе.

Release APK 0.1.3 (versionCode 4), x86_64, собран через Docker. Подпись проверена `apksigner` и совпадает с предыдущей версией; JavaScript включён в APK. Через `aapt2` проверены ресурсы адаптивного значка: применяется слой из исходного логотипа с надписью, отдельного одноцветного слоя нет. Скомпилированное изображение значка извлечено из APK и просмотрено; рисунок и название сохранены. Контрольная сумма записана в `artifacts/lapki-android.apk.sha256`.

Светлая обводка рекомендованного значка в нижнем ряду может добавляться Android Launcher. В меню такого ярлыка `Pin Prediction` закрепляет его и убирает кольцо рекомендации. [Реализация Android](https://android.googlesource.com/platform/packages/apps/Launcher3/+/533abfb4438a7becbffbcca169edb5a318aa9dcc/quickstep/src/com/android/launcher3/uioverrides/PredictedAppIcon.java).

У зависимостей Expo SDK 57 остаются предупреждения `npm audit`, включая инструменты сборки. Автоматический `audit fix --force` предлагает несовместимые версии SDK и здесь не применяется. Повреждённые входящие Android URI отбрасываются до разбора Expo Router.

Модели и правила согласованы с `lapki-frontend` (`src/commerce-dto.ts`, `src/validation.ts`, `src/commerce.ts`, `src/live-customer.tsx`). Backend и web-клиент не изменяются.
